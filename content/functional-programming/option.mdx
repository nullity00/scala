---
title: 'Option: Modeling Absence'
summary: Replacing null with Option.
---

Scala discourages `null`. Instead, a value that might be missing is wrapped in `Option[T]`, which
is either `Some(value)` or `None`. This forces you to handle the "missing" case at compile time
instead of discovering it as a runtime `NullPointerException`.

```scala
def findUser(id: Int): Option[String] =
  if id == 1 then Some("Ada") else None

val result = findUser(1)
println(result.getOrElse("unknown"))   // Ada
println(findUser(2).getOrElse("unknown"))  // unknown
```

`Option` supports the same `map`/`filter`/`match` toolkit as collections, because it's treated as
a container holding zero or one values:

```scala
val name: Option[String] = Some("ada")
println(name.map(_.toUpperCase))   // Some(ADA)
```
